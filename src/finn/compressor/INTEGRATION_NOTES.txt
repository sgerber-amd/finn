================================================================================
 Compressor-Python -> FINN MVU Integration Notes
================================================================================
 This file documents the design, implementation, and current status of a
 LUT-based compressor-tree dot product module (dotp_comp) integrated as a
 drop-in replacement for DSP-based compute cores in FINN's MVU.

 Last updated: 2026-03-17

================================================================================
 1. GOAL
================================================================================

Automatically use LUT-based compressor trees instead of DSP slices for small
operand widths (WW < 4, AW < 4) in FINN's Matrix-Vector Unit (MVU).  The
selection is transparent — determined by a localparam in mvu_vvu_axi.sv.

The compressor approach saves DSP resources for binary/ternary weight networks
(WW=1,2 and AW=1,2) where DSP slices are vastly underutilised.

================================================================================
 2. ARCHITECTURE
================================================================================

Two repositories are involved:

  compressor-python/         — Python generator + HDL templates + tests
  finn/finn-rtllib/mvu/      — FINN MVU RTL (integration target)

The path through the design is:

  mvu_vvu_axi.sv
    └─ localparam USE_COMPRESSOR = IS_MVU && !PUMPED_COMPUTE
                                   && (WEIGHT_WIDTH < 4)
                                   && (ACTIVATION_WIDTH < 4)
    └─ if(USE_COMPRESSOR) → dotp_comp.sv (template)
                               └─ mul_comp_map.sv (interface)
                               └─ $COMP_MODULE_NAME$ (generated core)

  dotp_comp.sv is a TEMPLATE file.  The placeholder $COMP_MODULE_NAME$ is
  replaced at code generation time with the config-specific compressor
  module name (e.g., comp_8xs2s2).  This follows the same template pattern
  as mvu_vvu_axi_wrapper.v.

  The generated compressor core is produced by:
    python dotp_finn.py --simd 8 --ww 2 --aw 2 --accu_width 16 \
                        --signed_activations -o <output_dir>

================================================================================
 3. PARAMETER MAPPING
================================================================================

 FINN parameter           Compressor parameter   Notes
 ----------------------- ---------------------- ------------------------------
 SIMD                    N                      # of multiply pairs per cycle
 WEIGHT_WIDTH            NA (or NB)             See "Operand Ordering" below
 ACTIVATION_WIDTH        NB (or NA)             See "Operand Ordering" below
 1 (weights always signed) SIGNED_A = 1         FINN convention
 SIGNED_ACTIVATIONS      SIGNED_B               Activation signedness
 PE                      (replicated)           PE independent comp instances
 ACCU_WIDTH              accumulator_width      Feedback accumulator width
 COMP_PIPELINE_DEPTH     delay (from generator) Pipeline stages in generated core

 Signal mapping (dotp_comp.sv ports → generated core ports):
   last             → rst (AccumulatorStage)    Resets accum for new dot prod
   zero             → en_neg (AccumStage)       Zeros pipeline input regs
   en               → en                        Clock enable on ALL registers
   rst (global)     → ORed into rst, en_neg     Initialises everything
   vld              → L[PIPELINE_DEPTH]         Output of last-delay pipeline

Operand Ordering:
  mul_comp_map requires NA >= NB.
  - If WW >= AW:  NA=WW, NB=AW, SA=1, SB=SIGNED_ACT  (normal wiring)
  - If WW <  AW:  NA=AW, NB=WW, SA=SIGNED_ACT, SB=1  (swapped)
  Both Python (dotp_finn.py compute_params) and RTL (dotp_comp.sv SWAPPED
  localparam) use the same swap logic — >= means not swapped.

================================================================================
 4. MODULE NAMING AND VIVADO NAMESPACE
================================================================================

Problem:
  FINN uses `add_files -norecurse` with a flat Vivado namespace.  If two
  MVU nodes have different compressor configurations, a fixed module name
  (`module comp`) would cause duplicate module elaboration errors.

Solution:
  Config-signature-based naming.  The module name encodes the configuration:
    comp_<sig>.sv  where sig = {N}x{s|u}{NA}{s|u}{NB}
  Examples: comp_8xs2s2, comp_8xs1u1, comp_16xs2s2

  Two nodes with the SAME (SIMD, WW, AW, signedness) share one comp_<sig>
  module — safe (identical RTL).  Two nodes with DIFFERENT configs get
  different module names — no collision.

  dotp_comp.sv uses $COMP_MODULE_NAME$ as a placeholder, expanded per node.

  Note: ACCU_WIDTH is NOT encoded in the signature.  Two nodes with the
  same operand config but different ACCU_WIDTH would collide.  In practice,
  FINN deterministically computes ACCU_WIDTH from the same inputs, so this
  is unlikely but not enforced.  If needed, encode as comp_8xs2s2_a16.

================================================================================
 5. GENERATED OUTPUT
================================================================================

For each configuration, dotp_finn.py generates ONE file:

  comp_<sig>.sv  — the compressor core with fused accumulator
    - Ports: clk, in[W-1:0], in_2[W-1:0], rst, en_neg, en, out[ACCU-1:0]
    - Internal: InputStage → GateAbsorption → CompressionStages →
                PipelineStage(s) → AccumulatorStage (final adder + feedback)
    - abs_term absorbed as constant inputs (zero hardware cost).
    - rst/en_neg/en delayed through pipeline to reach accumulator in sync.

The static wrapper dotp_comp.sv (template) handles:
  - PE-parallel instantiation of comp_<sig>
  - mul_comp_map broadcasting and column-major flattening
  - L[1:DEPTH] shift register for last → vld timing
  - Operand swap when ACTIVATION_WIDTH > WEIGHT_WIDTH

================================================================================
 6. DESIGN DECISIONS
================================================================================

Fused Accumulation:
  The accumulator feedback register is an extra input to the compressor
  tree's final adder, in contrast to a separate adder after the compressor.
  Saves one full adder width of LUTs.

Abs_term Inside Feedback (via Constant Absorption):
  The Baugh-Wooley/signed encoding correction constant (abs_term) is
  absorbed into the compressor tree as constant inputs (ConstantOne).
  Applied every accumulation cycle automatically.  Synthesis optimises
  constant inputs to wire rewiring (zero hardware cost).
  Previous approach added abs_term outside the feedback loop, which
  produced incorrect results for multi-cycle accumulations.

En-Gated Rst Pattern:
  When both en and rst are present on a Logic node, the generated SV is:
    if (en) begin
        if (rst_del) reg <= 1'b0;
        else         reg <= data;
    end
  Preserves accumulated state during stalls (en=0), matching DSP58 CE
  behavior.

Rst Delay Init:
  Rst delay chain registers initialised to 1 (logic logic_0 = 1'b1;).
  Ensures the accumulator feedback starts at zero even when en has never
  been asserted (rst delay regs can't capture initial rst=1 if en=0
  during global reset).

Static Template vs Generated Wrapper:
  dotp_comp.sv is a fixed, parametric template rather than a per-config
  generated wrapper.  Only the compressor core (comp_<sig>.sv) is
  generated.  This gives:
  - Reviewable, version-controlled RTL
  - Consistent style guide compliance
  - Single source of truth for PE/SIMD/operand-swap logic
  Per-node customisation is via $COMP_MODULE_NAME$ template expansion.

map0 Instance for Type Queries:
  A module-scope mul_comp_map instance (map0) exists solely to extract NM
  via $bits(map0.oa) and call columns()/height() in always_comb flatten.
  Its oa/ob outputs are not functionally used — the normal compressor-
  python flow dual-purposes map0 for the first operand pair, but the FINN
  flow creates all functional instances inside the PE generate.  The dummy
  wiring is a SystemVerilog limitation (interface ports must be connected).

================================================================================
 8. FINN PYTHON INTEGRATION (NOT DONE)
================================================================================

The FINN Python side (matrixvectoractivation_rtl.py) has NOT been modified.
This means the compressor path works in standalone tests but would fail in
an actual FINN build.  Required changes:

  prepare_codegen_default():
    - Add code_gen_dict["$COMP_PIPELINE_DEPTH$"] = [str(comp_delay)]
      for compressor configs, [str(1)] otherwise.  Currently this template
      variable is NEVER substituted — the literal string $COMP_PIPELINE_DEPTH$
      would remain in the generated wrapper, causing a Verilog parse error.

  generate_hdl():
    - Detect compressor eligibility (mirror USE_COMPRESSOR localparam)
    - Invoke dotp_finn.py generator (subprocess or importable API)
    - Capture comp_delay from return value
    - Read dotp_comp.sv as second template, replace $COMP_MODULE_NAME$
    - Write expanded dotp_comp.sv to code_gen_dir

  instantiate_ip() / get_rtl_file_list():
    - Conditionally add dotp_comp.sv (expanded), mul_comp_map.sv, and
      comp_<sig>.sv to source file lists

  compressor-python is NOT a pip-installable package (no __init__.py, no
  package structure).  Either restructure for import, or use subprocess.

================================================================================
 9. BUGS IDENTIFIED AND FIXED
================================================================================

BUG 1: Pipeline depth double-counted
  Compressor.delay already includes +1 for AccumulatorStage.  Generator
  added another +1.  Fix: total_delay = comp_delay (no extra +1).

BUG 2: Rst delay uninitialised under en-gating
  logic_0 (delayed rst) stays X during reset because en=0.
  Fix: Init rst delay registers to 1 (logic logic_0 = 1'b1).

BUG 3: Rst not gated by en (stall safety)
  Old: if(rst) ... else if(en) ...  clears state during stalls.
  Fix: if(en) begin if(rst) ... else ... end

BUG 4: L shift register out-of-bounds for PIPELINE_DEPTH=1
  L[1:0] on [1:1] vector.  Fix: conditionally omit shift tail.

BUG 5: Abs_term outside accumulation loop
  Result off by (K-1)*abs_term for K cycles.  Fix: absorb as constants.

BUG 6: Testbench drain cycles caused spurious output
  Fix: removed drain cycles, en=0 after data.

BUG 7: Test runner race condition on shared comp files
  Fix: two-phase runner (sequential generation, parallel simulation).

================================================================================
 11. KNOWN ISSUES AND SHORTCOMINGS
================================================================================

CRITICAL — FINN Python integration not done (see §8)
  $COMP_PIPELINE_DEPTH$ not substituted in wrapper template.
  dotp_comp.sv, mul_comp_map.sv, comp_<sig>.sv not in file lists.
  No generator invocation from Python.

MEDIUM — LOOKAHEAD8 GEA/GEB port unconnected (Versal)
  Blocks configs where final adder carry chain > ~16 bits.
  Practically limits to WW < 4, AW < 4 (which is the intended range).

MEDIUM — ACCU_WIDTH not in module signature
  Different ACCU_WIDTH with same operand config would collide.
  Low probability in practice but not enforced.

MEDIUM — No synthesis verification
  Only XSim behavioural simulation.  Area/timing unverified.

MEDIUM — COMP_PIPELINE_DEPTH=0 degeneracy
  L[1:0] would be 2 bits, not empty.  Guarded by initial assert >= 1.

LOW — Generated code does not follow style guide
  Names like logic_0, wire_238 — inherent to Python generator's emitter.

LOW — dotp_comp.sv exists in two locations
  finn/finn-rtllib/mvu/dotp_comp.sv and compressor-python/hdl/dotp_comp.sv
  must be kept in sync manually.  No mechanism to detect drift.

LOW — compute_abs_term() in dotp_finn.py is dead code
  Never called — abs_term is absorbed inside generate_comp_module().

LOW — en hardwired to '1 in mvu_vvu_axi.sv
  Correct (matches DSP cores) but suboptimal for dynamic power.

LOW — 7-Series target untested
  LUT6_2 + CARRY4 path exists but never exercised in integration flow.

 12. USAGE
================================================================================

Generate a compressor core:
  cd compressor-python/src
  python dotp_finn.py --simd 8 --ww 2 --aw 2 --accu_width 16 \
      --signed_activations --target Versal -o ../gen/my_config

Run all tests:
  cd compressor-python && bash run_tests.sh           # 21 core tests
  cd compressor-python && bash run_dotp_comp_tests.sh  # 8 dotp_comp tests
  cd finn/finn-rtllib/mvu/tb && bash run_mvu_comp_tests.sh  # 4 MVU tests
